# 이메일·비밀번호 정식 로그인

## 배경

`docs/decisions/user-identity.md`에서 확정한 대로, 첫 스펙(`trip-weather`)의
비밀번호 없는 이메일 식별을 이메일(아이디)과 비밀번호로 가입·로그인하는
정식 방식으로 대체한다. 구글·카카오 로그인과 비밀번호 찾기(이메일 재설정)는
이번 스펙에서 다루지 않는다 — 사용자와 상의해 범위를 좁혔다(아래 "범위
밖" 참고).

## 사용자 결과 시나리오

1. **회원가입** — 이메일(아이디)과 비밀번호를 입력해 계정을 만들면, 별도
   확인 절차 없이 바로 로그인된 상태로 마이 여행 화면으로 이동한다.
2. **로그인** — 가입한 이메일과 비밀번호를 입력하면 로그인되고, 그 계정에
   저장된 여행 목록이 보인다.
3. **잘못된 비밀번호** — 틀린 비밀번호로 로그인을 시도하면 오류 안내가
   뜨고 로그인되지 않는다.
4. **중복 가입 방지** — 이미 가입된 이메일로 다시 가입을 시도하면 실패
   안내가 뜬다.
5. **재접속** — 로그아웃 후 같은 계정으로 다시 로그인하면 이전에 만든
   여행 목록이 그대로 남아 있다.
6. **계정 간 격리** — 다른 계정으로 로그인하면 앞선 계정의 여행 목록이
   보이지 않는다.

## 승인된 범위

- 이메일(아이디)과 비밀번호로 회원가입한다. 가입 즉시 로그인된 상태가
  된다.
- 이메일과 비밀번호로 로그인한다. 로그아웃 기능은 그대로 유지한다.
- 비밀번호는 안전하게 저장되어(평문으로 보관되지 않음), 서버 관리자도
  원문을 볼 수 없다.
- 기존에 구현된 마이 여행 목록·여행 만들기·여행 상세(타임라인·지도 등)
  기능은 그대로 유지한다. 로그인 주체가 이메일 문자열에서 정식 계정으로
  바뀔 뿐, 여행 관련 동작은 달라지지 않는다.
- 기존에 이메일만으로 만들어졌던 계정·여행 데이터는 새 로그인 방식으로
  이어지지 않는다. 이번 전환 이후에는 새로 가입해야 한다.

## 관찰 가능한 인수 기준

- 새 이메일과 비밀번호로 가입하면 확인 메일을 기다리지 않고 바로 마이
  여행 화면이 보인다.
- 가입한 이메일·비밀번호로 로그인하면 그 계정의 여행 목록이 보인다.
- 같은 이메일에 틀린 비밀번호를 입력하면 로그인이 거부되고 오류 문구가
  보인다.
- 이미 존재하는 이메일로 가입을 시도하면 거부되고 안내 문구가 보인다.
- 로그아웃 후 같은 계정으로 재접속하면 이전 여행 목록이 그대로 있다.
- 계정 A로 만든 여행은 계정 B로 로그인했을 때 보이지 않는다.

## 설정된 제약과 근거

- **비밀번호 찾기(이메일 재설정) 제외**: 이 프로젝트에 연결된 Supabase의
  기본 이메일 발송 기능은 프로젝트 팀 멤버로 등록된 주소로만 메일을 보낼
  수 있고 시간당 2통으로 제한된다. 실제 가입자에게는 재설정 메일이 가지
  않으므로, 별도 이메일 발송 서비스(SMTP) 연동 없이는 정상 동작하지
  않는다. 새 서비스 가입은 범위를 다시 키우는 일이라, 사용자와 상의해
  이번 스펙에서는 빼기로 했다.
- **가입 즉시 로그인(이메일 확인 절차 없음)**: 같은 이유(기본 이메일
  발송 제약)로, 가입 확인 메일도 실제 가입자에게 가지 않는다. 확인을
  요구하면 오히려 아무도 가입을 완료할 수 없으므로, 확인 없이 즉시
  가입이 끝나도록 한다.
- **구글·카카오 로그인 제외**: `docs/decisions/user-identity.md`에서 이미
  범위 밖으로 정리했다.

## 가정

- 비밀번호 최소 길이 등 세부 정책은 인증 공급자(Supabase Auth)의 기본값을
  따른다. 저비용 가정이며 필요해지면 바꿀 수 있다.
- 이메일(아이디) 외의 추가 가입 정보(닉네임 등)는 받지 않는다.

## 범위 밖

- 비밀번호 찾기(이메일 재설정): "설정된 제약과 근거"에서 설명한 이메일
  발송 제약 때문에 이번 스펙에서 제외한다. 커스텀 SMTP를 연동하기로
  결정하면 별도 스펙으로 다룬다.
- 구글·카카오 소셜 로그인: `docs/decisions/user-identity.md`에서 이미
  범위 밖으로 확정했다.
- 가입 확인 메일, 이메일 변경, 계정 삭제: 이번 전환의 핵심(가입·로그인)이
  아니므로 다루지 않는다.
- 기존 이메일 전용 계정의 데이터 이관: 테스트 단계의 데이터라 이관 없이
  새로 가입하는 것으로 처리한다.

## 남은 리스크

- 비밀번호를 잊으면 현재는 계정을 되찾을 방법이 없다. 실사용자에게 열기
  전에는 반드시 비밀번호 찾기(또는 계정 복구 수단)를 마련해야 한다.
- 회원가입에 확인 절차가 없으므로, 실제 이메일 소유 여부는 검증되지
  않는다. 실사용 단계로 넘어가기 전에 재검토가 필요하다.
