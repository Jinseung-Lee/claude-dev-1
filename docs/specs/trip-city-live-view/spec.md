# 여행지 실시간 영상·복장 참고

## 배경

여행 일정에 등록한 도시의 날씨 수치만으로는 "실제로 사람들이 어떻게 입고
다니는지", "우산을 써야 하는지" 같은 현지 감각을 파악하기 어렵다. 이 스펙은
여행 상세 화면에서 도시의 공개 실시간 영상을 함께 보여주고, 날씨 수치를
체감온도·복장 참고 문구로 보조해서 이 감각을 채운다.

## 사실 확인

- **Windy Webcams API**: API 키와 회원가입이 필수다. 무료 요금제가 있지만
  이미지 URL 토큰이 10분마다 만료된다. 사용자와 상의해 이번 스펙에서는
  제외하기로 했다.
- **Windy 웹캠 embed 위젯**: API 키 없이 쓸 수 있지만, 약관상 상업적
  애플리케이션에서의 iframe 사용을 금지하고 미디어 용도로만 허용한다.
  라이선스 위험이 있어 제외한다.
- **런던 TfL·싱가포르 LTA·뉴욕 DOT·서울 TOPIS 등 도시별 공식 API**: 각각
  별도 신청·계약 절차가 있고 특정 도시에만 적용된다. 사용자가 어떤 도시든
  자유롭게 여행에 등록하는 이 앱의 구조와 맞지 않아 제외한다.
- **Open-Meteo**: 이미 연동되어 있고, 체감온도(`apparent_temperature`)와
  풍속(`wind_speed`)도 인증 없이 제공하는 것을 확인했다.
- 결론: API 키 없이 실현 가능한 방법은, 공식 채널이 임베드를 허용한
  유튜브 라이브 영상을 사람이 직접 조사해 미리 등록해 두는 것뿐이다. 이
  방법으로 진행하기로 사용자와 합의했다.

## 사용자 결과 시나리오

1. **영상이 있는 도시** — 여행 상세 화면에서 실시간 영상이 등록된 도시를
   보면, 그 도시의 공개 라이브 영상을 볼 수 있다.
2. **영상이 없는 도시** — 아직 영상을 등록하지 않은 도시는 영상 없이
   날씨(체감온도 포함)와 복장 참고 문구만 보인다. 오류나 빈 화면이
   아니다.
3. **복장 참고** — 어떤 도시든, 그날의 체감온도와 강수·바람 상태에 맞는
   복장 참고 문구(반팔/재킷/우산 등)를 볼 수 있다.

## 승인된 범위

- 여행 상세 화면(`/trips/[id]`)에서 도시별로 실시간 영상을 볼 수 있는
  요소를 추가한다.
- 실시간 영상은 사전에 조사해 등록해 둔 도시 목록에서만 제공된다. 최소
  2개 이상의 도시로 시작하고, 각 영상은 공식 채널이 임베드를 명시적으로
  허용한 것만 쓴다(뒤에 있는 "등록 절차" 참고).
- 등록되지 않은 도시는 영상 영역 대신 "이 도시의 실시간 영상은 아직
  없습니다" 같은 안내를 보여주고, 날씨는 그대로 보여준다.
- 날씨 정보에 체감온도를 추가하고, 아래 기준으로 만든 복장 참고 문구를
  덧붙인다(수치 날씨를 대체하지 않는 보조 문구).
  - 체감 28°C 이상: 반팔·가벼운 옷
  - 20~27°C: 반팔 또는 얇은 겉옷
  - 12~19°C: 긴팔·가벼운 재킷
  - 5~11°C: 코트 또는 보온 재킷
  - 4°C 이하: 두꺼운 외투·방한용품
  - 강수가 있으면 우산·방수 신발 문구를, 풍속이 높으면 바람막이 문구를
    덧붙인다.

## 관찰 가능한 인수 기준

- 영상이 등록된 도시가 포함된 날짜를 보면, 그 도시의 실시간 영상이
  재생되거나 표시된다.
- 영상이 등록되지 않은 도시는 영상 영역에 안내 문구가 뜨고, 나머지 날씨
  정보는 정상적으로 보인다.
- 아무 날짜나 선택해도 체감온도가 함께 표시된다.
- 체감온도가 28°C 이상인 날짜에는 "반팔"류 문구가, 4°C 이하인 날짜에는
  "두꺼운 외투"류 문구가 보인다.
- 강수량이 0보다 큰 날짜에는 우산 관련 문구가 추가로 보인다.

## 설정된 제약과 근거

- **인증 없는 유튜브 임베드 + 수동 큐레이션**: "사실 확인"에서 정리한
  대로, 조사 가능한 무인증 방법 중 라이선스 위험이 없고 이 앱의 자유
  도시 등록 구조와 맞는 유일한 방법이다.
- **미등록 도시는 날씨만**: 사용자와 이미 이 방향으로 합의했다. 영상
  커버리지보다 표시 권리를 지키는 것이 우선이라는 원 구축안의 원칙과도
  같다.
- **복장 참고 기준 수치**: 사용자가 제공한 구축안의 체감온도 구간을
  그대로 따른다.

## 가정

- 첫 스펙에서 실제로 등록할 도시와 영상 채널은 구현 단계에서 조사해서
  정한다. 조사 결과 확실히 공식·임베드 허용으로 확인되는 도시가 2개
  미만이면, 그 사실을 알리고 범위를 조정한다.
- 영상 재생이 실패하면(채널 삭제, 임베드 차단 등) 영상 없는 상태와
  동일하게 안내 문구로 대체한다.

## 범위 밖

- Windy Webcams API, 도시별 공식 교통 카메라 API(TfL·LTA·NYC DOT·서울
  TOPIS) 연동: "사실 확인"에서 정리한 이유로 이번 스펙에서 제외한다.
  API 키를 발급받기로 결정이 바뀌면 별도 스펙으로 다룬다.
- 얼굴 인식, 자동 복장 분석, 영상 저장·재배포: 애초에 다루지 않는다.
  사용자가 화면을 직접 보고 참고하는 용도로 한정한다.
- 영상 만료 시각 표시, 갱신 주기 관리 같은 운영 기능: 유튜브 라이브
  임베드는 별도 토큰 만료가 없어 이번 스펙에서 필요하지 않다.

## 남은 리스크

- 수동으로 큐레이션한 영상은 시간이 지나면 채널이 사라지거나 비공개로
  바뀔 수 있다. 정기적인 점검이 필요하다는 점을 알아둬야 한다.
- 영상 속 인물이 실제로 보일지, 밤 시간대라 안 보일지는 그 시점의 실제
  현지 시간에 달려 있다. 화면에 "낮/밤" 같은 설명은 이번 스펙 범위 밖이다.
