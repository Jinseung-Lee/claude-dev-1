# 지도 기반 도시 선택

## 배경

`docs/specs/trip-weather/`에서 만든 여행 만들기 화면은 도시 이름을 텍스트로 직접
입력하는 방식이다(PRODUCT.md에 "도시 검색·선택 방식 미정"으로 남아 있던 부분). 이
스펙은 그 화면에 지도를 추가해서, 도시를 검색하고 지도 위에서 눈으로 확인하며
선택할 수 있게 한다. 지도 라이브러리와 선택 방식은
`docs/decisions/map-integration.md`에서 이미 정했다: Leaflet + OpenStreetMap,
"검색 → 마커 표시 → 마커 클릭으로 확정" 방식이다.

## 사용자 결과 시나리오

1. **검색해서 지도에서 확인** — 도시 이름을 검색하면 지도 위에 마커가 뜨고,
   그 마커를 클릭하면 그 도시가 방문 도시로 확정된다.
2. **도시를 추가할 때마다 지도가 갱신** — 도시를 하나 추가할 때마다 지도에 그
   도시의 마커가 남고, 지도가 그 위치를 보여주도록 이동한다.
3. **전체 일정 확정 시 전체 도시가 보이도록 확대** — 방문 도시를 두 개 이상
   등록하면, 지도가 등록된 모든 도시가 한 화면에 들어오도록 자동으로
   확대·축소된다.
4. **기존 방식과의 호환** — 지도에서 선택하지 않고 도시 이름을 직접 타이핑해도
   여전히 여행을 만들 수 있다(지도는 선택을 돕는 보조 수단이지, 유일한 입력
   경로가 아니다).

## 승인된 범위

- 여행 만들기 화면(`/trips/new`)에 지도를 추가한다.
- 도시별 입력 행에 검색창을 두고, 이름을 입력하면 Open-Meteo geocoding
  검색 결과를 지도 위 마커로 보여준다. 마커를 클릭하면 그 도시의 이름과
  좌표가 해당 행에 채워진다.
- 도시 이름 텍스트 필드는 그대로 유지한다. 지도로 선택하면 텍스트 필드가
  자동으로 채워지고, 텍스트 필드를 직접 고쳐도 된다.
- 등록된 도시가 늘어날 때마다 지도의 마커도 함께 늘어난다. 도시가 2개 이상이면
  지도는 등록된 모든 도시가 보이도록 확대·축소 범위를 자동 조정한다(Leaflet의
  fitBounds에 해당하는 동작).

## 관찰 가능한 인수 기준

- 도시 이름을 검색하면 지도 위에 마커가 나타난다.
- 마커를 클릭하면 그 행의 도시 이름 필드가 검색한 도시 이름으로 채워진다.
- 도시를 2개 등록하면, 지도를 조작하지 않아도 두 도시 마커가 모두 화면 안에
  들어와 있다.
- 도시 이름을 지도 없이 텍스트로만 입력해도 기존과 동일하게 여행이 만들어진다.

## 설정된 제약과 근거

- **검색 → 마커 클릭 확정 방식, Leaflet + OpenStreetMap**:
  `docs/decisions/map-integration.md`에서 이미 근거와 함께 확정했다. Open-Meteo가
  역지오코딩을 지원하지 않아 임의 지점 클릭 방식은 쓰지 않는다.
- **텍스트 입력 방식 유지**: 지도 검색이 실패하거나(도시명을 못 찾는 경우 등) 지도
  없이 빠르게 입력하고 싶은 사용자를 위해 기존 경로를 없애지 않는다.

## 가정

- 검색 결과가 여러 개일 때(동명 도시 등) 상위 몇 개까지 마커로 보여줄지는 구현
  단계에서 정한다. 최소 1개 이상만 보장하면 된다.
- 지도의 초기 확대 수준(도시를 하나도 안 골랐을 때 세계지도가 얼마나 넓게
  보이는지)은 구현 단계에서 정한다.

## 범위 밖

- 이미 등록한 도시를 지도에서 드래그해 위치를 옮기는 기능은 다루지 않는다.
- 지도 위에서 직접 클릭해 좌표를 찍는 방식(역지오코딩)은
  `docs/decisions/map-integration.md`에서 이미 범위 밖으로 확정했다.

## 남은 리스크

- Leaflet은 서버 사이드 렌더링과 함께 쓰면 `window` 객체가 없어 오류가 나는
  것으로 알려져 있어, 클라이언트 전용으로 로드해야 한다. 실제 구현 시 화면이
  깨지지 않는지 반드시 런타임에서 확인해야 한다.
