# Map integration

## Decisions

- 지도는 Leaflet + OpenStreetMap 타일을 쓴다. API 키나 계정 등록이 필요 없다.
- 지도에서 도시를 고르는 방식은 "검색 → 지도에 마커 표시 → 마커 클릭으로 확정"이다.
  지도의 임의 지점을 클릭해 근처 도시명을 자동으로 알아내는 방식(역지오코딩)은
  쓰지 않는다.

## Boundaries

- 이 결정은 지도가 필요한 모든 화면(여행 만들기의 도시 선택, 여행 상세의 경로 지도
  등)에 적용된다.
- Mapbox나 Google Maps 같은 API 키가 필요한 지도 서비스는 이 결정의 범위 밖이다.

## Why

지금 쓰는 Open-Meteo geocoding API는 이름 → 좌표(forward) 검색만 지원하고,
좌표 → 도시명(reverse) 변환은 지원하지 않는다(`/v1/reverse` 호출 시 404). 임의
지점 클릭 방식을 쓰려면 별도의 역지오코딩 API(OpenStreetMap Nominatim 등)를
추가로 연동해야 하고, 엉뚱한 좌표를 클릭했을 때 도시가 잘못 잡히는 문제도 생긴다.
검색 기반 마커 확정 방식은 이미 연동된 Open-Meteo 검색만으로 구현되고, 사용자가
어떤 도시를 선택했는지 항상 명확하다.

지도 라이브러리는 Leaflet을 선택했다. 인증이 필요 없어 이 프로젝트가 지금까지
지켜온 "무인증 우선" 기조와 맞고, 여러 마커를 한 화면에 자동으로 맞춰 보여주는
기능(fitBounds)도 표준으로 제공해 "일정 확정 시 전체 도시가 보이도록 확대"
요구를 그대로 구현할 수 있다.

## Reconsider when

- 지도에 더 세밀한 스타일링이나 3D 지형, 실시간 트래픽 같은 고급 기능이
  필요해지는 시점: 이때는 Mapbox 등 유료/API 키 기반 서비스 재검토가 필요하다.

## Still-rejected alternatives

- 지도 임의 지점 클릭 + 역지오코딩 — 별도 API 연동과 오탐 처리 비용이 커서 보류.
- Mapbox GL — API 키·계정 등록이 필요해 이번 스펙의 무인증 기조와 맞지 않아 보류;
  고급 지도 기능이 필요해지면 재검토.
